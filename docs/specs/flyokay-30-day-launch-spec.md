# FLYOKAY Shopify Theme：30 天首发与结账关键路径规格

> 正式线上规格：GitHub Issue #1<br>
> 周期：2026-08-10 至 2026-09-08（30 个日历日；约 154 小时）<br>
> 首发市场与语言：美国、英文<br>
> 状态：Draft / `needs-info`。任何发布硬门未满足，计划暂停在未发布主题，不以压缩测试换取上线。

## 1. 首发目标

在 30 天内上线一个轻量、可编辑、可购买的 FLYOKAY Shopify 店铺。客户必须能：

1. 理解这是使用 FLYOKAY App 的可自定义 LED 飞行球；定制在购后完成，不是结账上传。
2. 选择正确的硬件外壳颜色，并看到与其对应的真实产品图片。
3. 从产品页顺利加购，在购物车确认商品/价格/优惠/运费信息，然后进入 Shopify 托管结账。
4. 在结账中获得实际可用的配送方式与支付方式，完成测试订单；商家能在 Shopify 后台看到正确订单、付款、履约和退款处理路径。

## 2. 不可改变的原则

1. **购买闭环优先。** 页面视觉、3D、评价或动效均不能阻断“变体 → 加购 → 购物车 → 结账 → 订单确认”。
2. **Shopify 是商业事实唯一来源。** 产品、变体、价格、库存、折扣、税费、运费、支付、结账和订单由 Shopify 后台配置；主题只读取并展示它们。
3. **结账不是主题页面。** 当前基础 Shopify 计划下，主题不改写 Shopify 托管结账的支付表单或结账流程。主题负责正确生成 `checkout_url`；商家在 Shopify Admin 配置支付、配送、税费和可用的结账设置。若未来升级到 Shopify Plus，再单独评估结账扩展/定制范围。参考：[Shopify checkout.liquid 文档](https://shopify.dev/docs/storefronts/themes/architecture/layouts/checkout-liquid)。
4. **真实素材和批准文案优先。** 不用 AI 生成图替代事实性产品媒体；不猜测安全、成人监督、保修、退货或促销规则。
5. **3D 只能渐进增强。** 首发默认使用静态产品视觉；3D 只有在不影响性能、无障碍和变体购买时才接入。
6. **未确认功能安全延后。** 折扣、评价、首单优惠和复杂动画如果没有后台规则/供应商/验收证据，首发不显示，而不是用占位承诺。

## 3. 已确认的首发事实

- 品牌口号：**Make Your Message Fly**。
- 产品：可通过 FLYOKAY Bluetooth App 自定义图片、动态图片、Emoji 和文字的 LED 飞行球；客户无需注册 App 账户。
- 变体：`Blue / Purple` 与 `Black / Gold`，均为**硬件外壳色**，不是 LED 显示色；均价 **$49.99**。
- 包装：球体主体、Type-C 充电线、说明书、礼品包装盒。
- 使用建议：6+（建议使用年龄，不属于包装配置）、飞行 7–10 分钟、充电 20–25 分钟、0–40°C；建议在户外空旷区域使用，室内避免拥挤环境。
- 美国履约：工作日 48 小时内发货、3–5 个工作日配送、美国免邮；无人为损坏 14 天内退货，退款在 7 个工作日内处理。
- 合规、安全警示和电池运输资料已有内部证据；只公开已批准、面向客户的内容。

## 4. 30 天首发范围

### 必须交付的页面与功能

| 范围 | 首发必须具备的内容 | 商业/验收要求 |
| --- | --- | --- |
| 全局主题壳 | Header、footer、导航、cart 入口、政策链接、skip link、移动端布局 | 主题编辑器可修改；键盘可用；无 JavaScript 下有基本购买路径 |
| 落地页 / Landing | 产品是什么、礼物价值、真实场景、购后 App 流程、产品 CTA、App 链接/QR、订阅入口 | CTA 进入正确产品；不承诺结账上传；3D 有静态回退 |
| 商店页 / Store | 一产品的策展式展示 | 不伪造多商品网格、交叉销售或捆绑模块 |
| 产品页 / PDP | 真实媒体、`Shell color`、价格、库存、数量、加购、规格、App、配送、退货、FAQ | 两个变体均可由直接 URL 预选，媒体/价格/库存/加购状态同步 |
| 购物车 | 商品行、正确变体、数量、删除、价格、折扣（若实际启用）、结账按钮、运费/退货说明链接 | `checkout_url` 正确交接；不自行处理支付数据 |
| About Us | 品牌/礼物定位与批准的产品理念 | 不新增无法证实的品牌、性能或安全宣称 |
| How It Works | 蓝牙连接、购后 App 上传内容、展示/飞行、App 链接/QR | 与实际 App 和说明书完全一致 |
| FAQ / Contact | 高频购买问题与真实支持入口 | 只使用批准答案和联系信息 |
| Shipping & Returns | 免邮、处理、配送、退货、退款流程 | 与 Shopify 后台和批准政策一致 |
| Privacy / Terms | Shopify 政策页和批准法律文本 | 可从页脚和结账中访问 |
| 邮件订阅 | Shopify Email 的基础订阅和欢迎流程 | 未确认优惠时不发送或显示优惠码 |

### 不属于 30 天首发

- 公开用户作品上传、社区、点赞、下载、账户、审核或儿童数据处理。
- 结账时上传图片/内容定制。
- 深度 3D/WebGL、复杂 GSAP 动画或新增大体积前端依赖。
- 多语言、多货币、订阅、忠诚度、批发、国际市场和新产品扩展。
- 未在 Shopify 自动折扣中验证的“两件 20% off”、复杂捆绑/加购推荐。
- 任何未经批准的评价导入或伪造社会证明。

## 6. 支付与结账关键路径

### 6.1 责任边界

| 层级 | 负责方 | 必须验证的内容 |
| --- | --- | --- |
| 产品页与购物车 | 主题 + Shopify 商品数据 | 变体、媒体、价格、库存、数量、加购、购物车商品行、折扣呈现、结账按钮 |
| 结账设置 | Shopify Admin | 支付方式、配送地址收集、配送方式/费率、税费、结账品牌设置、订单通知、政策链接 |
| 支付表单与订单处理 | Shopify/已启用支付服务商 | 支付方法出现、成功/失败支付行为、订单确认、订单状态、退款/取消路径 |

### 6.2 必做的端到端测试（未发布主题与生产前测试）

每项均记录日期、测试人、设备/浏览器、变体、结果、截图或订单编号；任何失败都是发布阻塞项。

1. 打开两个直接变体 URL：确认对应颜色、图片、`$49.99`、库存和加购状态。
2. 各变体分别加购；在购物车确认正确商品名、变体名、数量、单价、小计和删除/数量调整。
3. 若 C1 启用：测试 1 件、2 件、变体混搭、排除/不可叠加情形，确认购物车与结账中的实际折扣一致。
4. 从购物车进入 Shopify 结账：确认没有报错、丢失商品行、错误价格或循环跳转。
5. 在美国有效测试地址下确认免邮/配送方法、税费、预计送达与政策链接与后台配置一致。
6. 确认被启用的支付方式实际出现；不得在主题中自建信用卡、PayPal 或钱包输入框。
7. 用 Shopify 支持且商家批准的测试方式完成至少一笔订单；确认订单确认页和订单确认邮件到达。
8. 在 Shopify Admin 核对订单中的变体、价格、折扣、配送、税费、付款状态、客户信息、履约状态和通知记录。
9. 按批准的操作方式测试取消/退款或至少完整核对退款权限、流程和客户通知；不得因测试而遗留真实客户订单或未处理资金。
10. 在手机、桌面、慢网和无 JavaScript 情况下重复主题可控部分（产品页与购物车）；结账页面只做实际用户流程验证。

## 8. 发布验收清单

发布仅在以下条件全部满足后进行：

- H1–H6 均有证据，且无未批准产品、安全、政策或支付事实。
- Landing、Store、PDP、cart、About、How It Works、FAQ/Contact、Shipping & Returns、Privacy、Terms 全部可达且移动端可用。
- 两种硬件外壳从直接 URL、PDP、cart 到 checkout 的结果正确。
- Shopify Admin 中实际支付、配送、税费、订单通知和测试订单流程通过；折扣/评价/优惠只在对应 C 门通过后显示。
- 不含 checkout-time upload、公共用户内容、未验证促销、假评价或对基础计划不可用的结账主题定制。
- Theme Check 无关键错误；键盘、焦点、无 JS 购买回退、主要小屏、图片/3D 失败回退和重要页面性能均通过。
- 当前生产主题、候选 commit、候选 theme ID、发布人、发布时间和回滚目标已记录。
- 商家对内容、声明、政策、促销（若有）、支持设备和候选主题给予书面批准。

## 9. 上线与回滚

1. 只发布已验收的未发布主题；保留当前生产主题作为可立即恢复的回滚目标。
2. 发布后立即在手机与桌面检查：首页、PDP、两种颜色、cart、checkout handoff、App 链接、政策、订单确认。
3. 出现支付失败、错误价格/折扣、配送/税费错误、法律/安全错误、购买阻断或严重无障碍/性能问题时，立刻回滚并在 GitHub 创建 Issue。
4. 上线后记录订单、订阅、App 点击、支持/退货反馈和性能信号；30 天首发范围外的需求只能在复盘后单独排期。
